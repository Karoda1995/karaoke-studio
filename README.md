# Кадр — караоке-студия

[Открыть редактор](https://karoda1995.github.io/karaoke-studio/)

Исходный код браузерной караоке-студии. Сайт публикуется через GitHub Pages из папки `docs` ветки `main`.

Браузерный редактор караоке с отдельными дорожками оригинала и минуса. Файлы обрабатываются на устройстве. API-ключ не нужен. Интернет требуется для первого скачивания моделей с Hugging Face / jsDelivr и загрузки шрифта.

## Две аудиодорожки
- **Оригинал с вокалом** — исходная песня или чистая вокальная дорожка. Используется для расшифровки, акустического выравнивания и редактирования на слух.
- **Минус** — отдельная инструментальная фонограмма. Используется для предпросмотра и экспорта без исходного вокала. Загрузка минуса сохраняет тайминги.
- «Слушать» переключает дорожки на общей шкале оригинала. Воспроизводится только выбранная дорожка.
- «Звук готового видео» выбирается отдельно. По умолчанию выбран минус. Если его нет, приложение попросит загрузить минус или явно выбрать оригинал; скрытой подмены нет.
- «Смещение минуса» исправляет разницу вступлений. Положительное значение запускает минус позже на шкале оригинала. Если минус имеет лишние 2 секунды в начале, укажите −2. Если оригинал имеет лишние 2 секунды, укажите +2. Различие темпа, монтажа или структуры одним сдвигом не исправить.
- Длительность общей шкалы — максимум длительности оригинала и смещённого минуса; в более короткой дорожке хвост остаётся без звука.

## Точное выравнивание текста
1. Загрузите оригинал с вокалом и минус от той же версии песни.
2. Вставьте полный точный текст, со всеми повторами припевов, по одной фразе на строку. Доступны TXT и LRC в UTF-8. Числа запишите словами; служебные подписи куплетов удалите.
3. Если текста нет, нажмите «Расшифровать оригинал в текст». Whisper Small (~500 МБ) создаст отдельный редактируемый черновик. Исходный текст не заменяется, пока вы не нажмёте «Вставить черновик в текст песни».
4. Исправьте слова и переносы строк, затем нажмите «Точно выровнять текст по вокалу».
5. Русская акустическая модель XLSR-53 рассчитывает вероятности букв по звуку. CTC-алгоритм ищет путь для вашего полного текста; заданные слова не заменяются распознанными. Границы слогов строятся по акустическим отметкам букв, без равномерного деления длительности слова.
6. «Точный» загружает квантизованную модель (~317 МБ). «Полная модель FP32» использует исходную численную точность, загружает ~1,26 ГБ и требует существенно больше памяти. Это не гарантия большей точности на каждой песне. Для начала достаточно первого режима.
7. Акустический анализ идёт фрагментами с перекрытием контекста; повторы на стыках не дублируются. Вступление и проигрыши не распределяются равномерно между словами.
8. Строки с низким акустическим совпадением или подозрительной длительностью помечаются «Уточнить». Это диагностические отметки, не измеренная вероятность ошибки.
9. Для сложных мест задайте границы строк вручную или через LRC, включите «Учитывать выставленные границы строк» и повторите выравнивание. Если аудио и режим модели не менялись, рассчитанная акустика повторно используется.

Русский текст поддерживается в точном режиме. Пение с растянутыми гласными, эффекты, бэк-вокал, сильное сопровождение и неверный текст всё ещё могут давать ошибки. Модель обучена на речи; стопроцентная точность на песнях не обещается. Чистая вокальная дорожка обычно удобнее для выравнивания, чем громкий полный микс. Акустическая сетка 20 мс — шаг расчёта, а не гарантия ошибки ±20 мс. Фрагменты более 20 минут и слишком большие матрицы выравнивания отклоняются с сообщением.

## Правка на слух
Нажмите строку, затем слово: доступны границы целого слова и каждого слога. Можно двигать общую границу соседних слогов, менять скорость воспроизведения, зациклить фразу, смотреть форму волны и переходить к отмеченным местам. Свой вариант деления задаётся знаком | (на|при|мер), после чего выравнивание выполняется заново.

«Черновая разметка» остаётся вспомогательным приблизительным режимом. «Отбивать слоги» записывает все слоги пробелом; при прерывании предыдущие тайминги восстанавливаются. Конец последнего слога при ручной записи приблизительный — поправьте его на слух.

## Видео и проекты
Добавьте фон, настройте плашку, цвет и формат кадра. Положительный сдвиг текста показывает подсветку позже.

Экспорт: выбранная отдельно дорожка, скорость 1× независимо от замедления предпросмотра, 30 кадров/с, HD / Full HD. MP4, если поддерживается MediaRecorder, иначе WebM. Конвертации WebM в MP4 нет. Запись идёт в реальном времени — держите вкладку на экране. Длинные видео требуют памяти.

Формат .karaoke версии 2 содержит обе аудиодорожки, смещение минуса, текст, фон, оформление и тайминги. Проекты версии 1 открываются: прежняя песня становится оригиналом. Автосохранения нет.


## Локальный запуск
Python 3, из папки проекта:

    python3 -m http.server 8879 --directory docs --bind 127.0.0.1

Откройте http://127.0.0.1:8879 в актуальном настольном Chrome или Safari. file:// не подходит для модульного worker.

## Проверки

    node tests/alignment.test.mjs
    node tests/transport.test.mjs

Проверены CTC-путь с повторяющимися буквами, тишина, неравномерные длительности слогов, ограничения строк и маршрутизация аудио, знак смещения, перемотка, скорость и завершение. Дополнительно выполнено настоящее акустическое распознавание синтезированной русской фразы: повтор фразы на длинной шкале, вступление, финальная тишина и слово через стык 16-секундных фрагментов. Это проверка реализации, не измерение качества на песне пользователя.

- https://huggingface.co/onnx-community/wav2vec2-large-xlsr-53-russian-ONNX

Модель XLSR-53 опубликована под Apache 2.0. Используется Transformers.js 3.8.1. Аудио не отправляется на сервис распознавания.

## Структура репозитория

- `docs/` — редактор и обработка аудио, публикуемые GitHub Pages.
- `tests/` — проверки выравнивания и переключения аудиодорожек.

После изменения файлов в `docs/` и отправки в `main` GitHub Pages автоматически обновляет сайт. Зависимости для запуска сайта устанавливать не нужно. Для тестов требуется Node.js 22 или новее.

Загружаемые пользователем песни, изображения, проекты и скачанные модели не хранятся в репозитории.

## Чередование строк и шрифт

На старте видны строки 1 (сверху) и 2 (снизу). Когда строка 1 заканчивается, на её месте плавно появляется строка 3, а строка 2 остаётся снизу и подсвечивается там. Затем снизу появляется строка 4, пока строка 3 поётся сверху. Строки чередуются до конца песни. После окончания последней фразы текст плавно исчезает. Во вступлениях и паузах будущие строки видны заранее.

В «Оформлении» выбирается шрифт: Manrope, Arial, Verdana, Georgia, Trebuchet MS или Courier New. Системные шрифты используют резервное семейство, если выбранный шрифт не установлен; Manrope загружается через существующее подключение Google Fonts. Регулятор «Плавность смены строк» задаёт длительность затухания и лёгкого сдвига; 0 мс отключает анимацию. Шрифт, размер и плавность сохраняются в проекте.

Предпросмотр и экспорт используют один renderer и время аудио: перемотка, повтор и запись видео дают одинаковую раскладку. Шрифт подготавливается до начала экспорта.

Проверка раскладки и отрисовки: `node tests/karaoke-renderer.test.mjs`.
